# Despliegue de n8n con Docker Compose en el VPS

Esta guía explica paso a paso cómo instalar y desplegar **n8n** (una plataforma de automatización de flujos de trabajo) en un servidor VPS utilizando **Docker Compose**, cómo solucionar problemas de permisos de volumen (`EACCES`) y cómo exponer la aplicación de forma segura con HTTPS a través de **Cloudflare Tunnel**.

---

## ¿Qué es n8n y por qué desplegarlo en Docker?

**n8n** es un sistema de automatización ejecutable en servidor propio (*self-hosted*). Permite conectar diferentes APIs y servicios (correo electrónico, Telegram, bases de datos, webhooks, etc.) mediante una interfaz gráfica basada en nodos.

### Ventajas de ejecutar n8n en un VPS con Docker:
- **Disponibilidad 24/7:** Al ejecutarse en el VPS, los flujos de trabajo se ejecutan de forma ininterrumpida.
- **Imagen oficial lista para usar:** La comunidad de n8n distribuye la imagen oficial `n8nio/n8n` en Docker Hub, lo que evita tener que instalar Node.js o gestionar dependencias manualmente.

---

## ¿Qué es Docker Compose?

`docker-compose` es una herramienta para definir y ejecutar aplicaciones compuestas por uno o varios contenedores mediante un archivo de configuración en formato YAML (`docker-compose.yml`).

### Principales ventajas:
1. **Configuración declarativa:** Parámetros como puertos, volúmenes y variables de entorno quedan guardados en un archivo, evitando ejecutar comandos largos manualmente.
2. **Orquestación simplificada:** Permite arrancar o detener el servicio completo con comandos sencillos como `docker-compose up -d` o `docker-compose down`.

> [!NOTE]
> En los archivos **YAML**, la sangría (espacios a la izquierda) define la jerarquía de la estructura. Utiliza siempre **espacios**, nunca tabuladores.

## 1. Conexión SSH y creación del directorio de trabajo

Accede al VPS mediante SSH:

```bash
ssh uservps@ipdelavps
```

Crea el directorio específico para la configuración de n8n y accede a él:

```bash
mkdir -p /home/uservps/n8n
cd /home/uservps/n8n
```

> [!IMPORTANT]
> `docker-compose` busca por defecto el archivo `docker-compose.yml` en la carpeta desde la que se ejecuta el comando. Asegúrate de estar dentro de `/home/uservps/n8n`.

---

## 2. Crear el archivo `docker-compose.yml`

Abre el editor `nano` para crear el archivo de configuración:

```bash
nano docker-compose.yml
```

Pega el siguiente contenido dentro del archivo:

```yaml
services:
  n8n:
    image: n8nio/n8n
    container_name: n8n
    restart: unless-stopped
    ports:
      - "5678:5678"
    volumes:
      - ~/.n8n:/home/node/.n8n
```

*(Guarda los cambios pulsando `Ctrl + O`, `Enter` y sal con `Ctrl + X`).*

### Explicación parámetro por parámetro:

- `services:` Define la lista de servicios/contenedores que componen la aplicación.
- `n8n:` Nombre interno asignado al servicio dentro del archivo Compose.
- `image: n8nio/n8n` Nombre de la imagen oficial alojada en Docker Hub.
- `container_name: n8n` Nombre único del contenedor para facilitar comandos como `docker logs n8n`.
- `restart: unless-stopped` Instruye a Docker a reiniciar el contenedor automáticamente en caso de caídas del proceso o reinicio del VPS.
- `ports: - "5678:5678"` Mapea el puerto `5678` del VPS (izquierda) con el puerto `5678` interno del contenedor (derecha).
- `volumes: - ~/.n8n:/home/node/.n8n` Enlaza el directorio local del VPS (`~/.n8n`) con la carpeta de datos interna de n8n (`/home/node/.n8n`), garantizando que las automatizaciones y credenciales no se pierdan al destruir el contenedor.

---

## 3. Iniciar el servicio con Docker Compose

Si `docker-compose` no está instalado en el VPS, puedes instalarlo mediante:

```bash
sudo apt update && sudo apt install docker-compose -y
```

Inicia el servicio en segundo plano (*detached mode*):

```bash
docker-compose up -d
```

### Comprobar el estado del contenedor:

```bash
docker ps
```

Debe mostrar el contenedor con estado `Up`:

```text
CONTAINER ID   IMAGE       COMMAND                  CREATED          STATUS          PORTS                                         NAMES
695956afbc78   n8nio/n8n   "tini -- /docker-ent…"   45 seconds ago   Up 44 seconds   0.0.0.0:5678->5678/tcp, [::]:5678->5678/tcp   n8n
```

## 4. Solución al problema de permisos (`EACCES: permission denied`)

Si el comando `docker ps` indica que el contenedor está en estado `Restarting`, comprueba los registros de error con:

```bash
docker logs n8n
```

### Error habitual:
`EACCES: permission denied, open '/home/node/.n8n/config'`

### Causa técnica:
Dentro del contenedor, n8n se ejecuta con el usuario interno `node` (UID `1000`). Si el directorio de volumen `~/.n8n` en el VPS fue creado por `root` u otro usuario con identificador diferente, Linux denegará el acceso de escritura a n8n.

### Solución paso a paso:

1. Detén el servicio:
```bash
docker-compose down
```

2. Asigna la propiedad del directorio de datos al usuario y grupo `1000`:
```bash
sudo chown -R 1000:1000 ~/.n8n
```

3. Vuelve a iniciar el contenedor:
```bash
docker-compose up -d
```

---

## 5. Acceso local y túnel SSH de prueba

Puedes acceder temporalmente a la interfaz web de n8n introduciendo la IP pública y el puerto en tu navegador:

```text
http://[IP_de_la_maquina_virtual]:5678
```

### Probar la interfaz mediante un Túnel SSH seguro

Si el puerto `5678` no está abierto en el firewall, puedes crear un túnel directo desde la terminal de tu **ordenador local**:

```bash
ssh -L 5678:localhost:5678 uservps@ipdelavps
```

Con la sesión SSH abierta, accede a `http://localhost:5678` desde el navegador de tu PC.

## 6. Configurar acceso seguro HTTPS con Cloudflare Tunnel

Para utilizar n8n en producción de forma segura, se recomienda cifrar el tráfico con **HTTPS** y asignar un nombre de dominio (ejemplo: `https://tunel.dominio.es`).

**Cloudflare Tunnel** (`cloudflared`) permite conectar el VPS con los servidores de Cloudflare mediante una conexión saliente, **sin necesidad de abrir puertos de entrada en el firewall del VPS**.

### Paso 6.1: Añadir la clave GPG de Cloudflare en el VPS

```bash
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-public-v2.gpg | sudo tee /usr/share/keyrings/cloudflare-public-v2.gpg >/dev/null
```

### Paso 6.2: Registrar el repositorio oficial

```bash
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-public-v2.gpg] https://pkg.cloudflare.com/cloudflared any main' | sudo tee /etc/apt/sources.list.d/cloudflared.list
```

### Paso 6.3: Instalar `cloudflared`

```bash
sudo apt-get update && sudo apt-get install cloudflared -y
```

### Paso 6.4: Instalar y vincular el servicio de túnel

Obtén el **token** de instalación desde el panel de Cloudflare Zero Trust (*Networks > Tunnels*) e instálalo como servicio del sistema:

```bash
sudo cloudflared service install el_token_que_nos_hayan_dado...
```

> [!WARNING]
> El token de Cloudflare contiene la credencial de autenticación de tu túnel. **Nunca lo publiques ni lo incluyas en repositorios de Git**.

### Paso 6.5: Configurar el *Public Hostname* en Cloudflare

En el panel de Cloudflare Zero Trust, configura el nombre de host público asignado al túnel:

- **Subdominio:** `tunel`
- **Dominio:** `dominio.es`
- **Tipo de servicio:** `HTTP`
- **URL / Target:** `localhost:5678`

A partir de este momento, las solicitudes enviadas a `https://tunel.dominio.es` serán cifradas por Cloudflare y redirigidas a través del túnel seguro hacia la aplicación n8n que escucha en `localhost:5678` dentro del VPS.
