# Guía: Migrar y desplegar WordPress en un VPS con Docker

En este tutorial se explica cómo migrar una web de WordPress alojada en un entorno local o servidor web previo hacia un servidor en la nube (VPS) utilizando Docker y Docker Compose.

---

## 1. Preparativos

1. **Descargar archivos**: Descarga la carpeta `wp-content` de tu sitio actual (preferiblemente comprimida en formato `.zip`) y haz una exportación (`.sql`) de tu base de datos actual.
2. **Organización local**: Guarda todo en una carpeta (por ejemplo, `carpeta-web`).
3. **Fichero de configuración**: Crea o añade el archivo `docker-compose.yml` en la raíz de esa misma carpeta.

---

## 2. Configurar el archivo docker-compose.yml

A continuación se muestra un ejemplo de plantilla usando las imágenes oficiales de MariaDB y WordPress:

```yaml
services:
  db:
    image: mariadb:11
    container_name: nombre_contenedor_db
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: claveroot
      MYSQL_DATABASE: nombre_db
      MYSQL_USER: nombre_user
      MYSQL_PASSWORD: claveuser
    volumes:
      - db_data:/var/lib/mysql

  wordpress:
    image: wordpress:latest
    container_name: nombre_contenedor_web
    restart: always
    ports:
      - "8081:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_NAME: nombre_db
      WORDPRESS_DB_USER: nombre_user
      WORDPRESS_DB_PASSWORD: claveuser
    volumes:
      - wp_data:/var/www/html
    depends_on:
      - db

volumes:
  db_data:
  wp_data:
```

> **Nota**: Ajusta el puerto del host (`8081:80`) según tus necesidades o configuraciones del servidor.

---

## 3. Subir ficheros al VPS

### 1. Acceder al servidor por SSH

```bash
ssh usuariovps@ipvps
```

### 2. Copiar la carpeta al servidor

Es recomendable subir la carpeta `wp-content` comprimida (`wp-content.zip`) para agilizar el proceso de transferencia vía `scp`:

```bash
scp -r carpeta-web usuariovps@ipvps:/home/uservps/carpeta-web
```

### 3. Entrar a la carpeta y descomprimir wp-content

```bash
cd carpeta-web
unzip wp-content.zip
```

---

## 4. Levantar los contenedores

Desde el directorio `carpeta-web` en el VPS, ejecuta:

```bash
docker compose up -d
```

Este comando descargará las imágenes necesarias (MariaDB y WordPress) y arrancará ambos contenedores en segundo plano (`-d`).

---

## 5. Comprobar el estado de los contenedores

Ejecuta `docker ps` para verificar que ambos contenedores están en estado `Up` y no en bucle de reinicio.

Si algo falla o un contenedor se detiene, puedes revisar los registros con:

```bash
docker logs nombre_contenedor_web
docker logs nombre_contenedor_db
```

---

## 6. Dar acceso a la web desde fuera (Dominio y SSL)

En lugar de abrir directamente los puertos del VPS a Internet, si usas **Cloudflare Tunnels**, puedes asociar tu dominio propio al puerto configurado en el `docker-compose.yml` (`8081`). De esta forma evitas exponer el VPS directamente a Internet.

---

## 7. Completar la instalación o migración

- **Si es una web totalmente nueva**: Entra desde el navegador a `http://ipvps:8081` o a tu dominio y completa el asistente inicial de WordPress.
- **Si estás migrando una web existente**: Puedes ignorar este paso y pasar directamente al **Punto 8**.

---

## 8. Volcar el contenido de la web en Docker

### 1. Copiar la carpeta wp-content al contenedor de WordPress

```bash
docker cp wp-content nombre_contenedor_web:/var/www/html/
```

### 2. Importar la base de datos

Importa tu archivo `.sql` en el contenedor de MariaDB (te solicitará la contraseña configurada previamente):

```bash
docker exec -i nombre_contenedor_db mariadb -u nombre_user -p nombre_db < nombre_fichero.sql
```

Si el sistema requiere especificar la clave directamente en la línea de comandos (sin espacio tras `-p`):

```bash
docker exec -i nombre_contenedor_db mariadb -u nombre_user -p"claveuser" nombre_db < nombre_fichero.sql
```

#### Explorar la base de datos desde dentro (Opcional)

Si necesitas acceder a la consola interactiva de MariaDB como `root`:

```bash
docker exec -it nombre_contenedor_db mariadb -u root -p
```

### 3. Probar el acceso desde el navegador

Una vez volcados los archivos y la base de datos, accede desde el navegador utilizando la IP del VPS y el puerto configurado:

- Sitio web: `http://ipvps:8081`
- Panel de administración: `http://ipvps:8081/wp-admin`

### 4. Verificar y actualizar la URL de la web en la base de datos

Para comprobar a qué dominio está apuntando la instalación en la tabla `wp_options`:

1. Entra a la base de datos en el contenedor:

```bash
docker exec -it nombre_contenedor_db mariadb -u nombre_user -p"claveuser" nombre_db
```

2. Consulta los registros de `siteurl` y `home`:

```sql
SELECT option_name, option_value
FROM wp_options
WHERE option_name IN ('siteurl','home');
```

3. Si en los resultados aparece la URL del sitio antiguo (ej. `https://midominioantiguo.es`), actualízala con el nuevo dominio:

```sql
UPDATE wp_options
SET option_value='https://dominio.es'
WHERE option_name IN ('siteurl','home');
EXIT;
```

### 5. Configurar la ruta de la aplicación en Cloudflare

Si utilizas Cloudflare:

1. Elimina los registros A y CNAME antiguos que apuntaban al hosting anterior.
2. Crea una **Ruta de Aplicación (Public Hostname)** apuntando al puerto configurado en el `docker-compose.yml` (`http://localhost:8081`).

---

## Conceptos clave: `docker exec -i` vs `docker exec -it`

- **`-i` (interactive)**: Mantiene abierta la entrada estándar (`stdin`). Se utiliza para enviar flujos de datos hacia el contenedor (como al volcar una base de datos con `< archivo.sql`).
- **`-t` (tty)**: Asigna una pseudoterminal con formato visual (colores, prompts y manejo de cursor).
- **`-it` (las dos juntas)**: Se usa para interactuar en tiempo real dentro del contenedor, por ejemplo al ejecutar una terminal interactiva (`bash` / `sh`) o al acceder a la CLI de MariaDB.

## Copia de seguridad (Backup) de la web

### 1. Archivos (`wp-content`)

Para respaldar la carpeta `wp-content`, puedes copiarla directamente desde el contenedor de WordPress:

```bash
docker cp nombre_contenedor_web:/var/www/html/wp-content ./wp-content-backup
```

### 2. Base de datos

Para exportar la base de datos desde el contenedor:

```bash
docker exec nombre_contenedor_db mysqldump -u nombre_user -p"claveuser" nombre_db > backup.sql
```

### 3. Descargar del VPS al equipo local

Para copiar el archivo generado desde el VPS a tu máquina local, ejecuta desde la terminal de tu ordenador:

```bash
scp usuariovps@ipvps:/ruta/en/vps/backup.sql ./
```

## Resolución de problemas comunes

### 1. Servicio `cloudflared` inactivo tras actualizar el sistema operativo del VPS

Puedes comprobar el estado del servicio de Cloudflare con el siguiente comando:

```bash
systemctl status cloudflared
```

Si el estado indica un fallo (`code=exited, status=255/EXCEPTION`), consulta los registros del sistema:

```bash
sudo journalctl -u cloudflared -n 50 --no-pager
```

Si aparece el mensaje `Failed to read token file: open /etc/cloudflared/token: no such file or directory`, indica que el archivo del token se ha eliminado durante la actualización.

**Pasos para solucionarlo**:

1. Vuelve a crear el archivo e introduce tu token:

```bash
sudo nano /etc/cloudflared/token
```

2. Para verificar si una actualización del sistema causó el fallo, puedes revisar el historial de paquetes:

```bash
grep -i cloudflared /var/log/apt/history.log
```

3. Finalmente, reinicia el servicio:

```bash
sudo systemctl restart cloudflared
```

---

### 2. Error 404 Not Found en páginas internas (sólo funciona la portada)

**Causa**:
WordPress requiere reglas de reescritura de URLs en el servidor Apache (archivo `.htaccess`). Al migrar la base de datos o montar el contenedor desde cero, el archivo `.htaccess` suele faltar en la raíz de WordPress, haciendo que solo la página de inicio funcione.

**Solución**:

1. Entra al panel de WordPress: `http://dominio.es/wp-admin`
2. Ve a **Ajustes > Enlaces permanentes**.
3. Sin modificar nada, pulsa el botón **Guardar cambios**. Esto generará automáticamente el archivo `.htaccess` correcto.

---

### 3. Imposibilidad de restablecer la contraseña en `wp-admin`

**Causa**:
Los contenedores recién creados no suelen incluir un servidor de correo (SMTP) configurado, por lo que la función " Restablecer contraseña por email" fallará.

**Solución (Cambiar la contraseña desde la base de datos)**:

1. Entra a la consola de MariaDB en el contenedor:

```bash
docker exec -it nombre_contenedor_db mariadb -u nombre_user -p"claveuser" nombre_db
```

2. Verifica el nombre exacto de tu usuario:

```sql
SELECT ID, user_login, user_email FROM wp_users;
```

3. Actualiza la contraseña aplicando el hash MD5:

```sql
UPDATE wp_users
SET user_pass = MD5('tu_nueva_contrasena')
WHERE user_login = 'tu_usuario_wordpress';
```

### 4. No puedo actualizar los plugins de Wordpress

- WordPress pide credenciales FTP cuando el proceso PHP (el que ejecuta WordPress) no tiene permisos de escritura directa sobre los archivos del sitio. Como no puede escribir, cae al método FTP como alternativa.
- En mi caso como la web la tengo dentro de un contenedor docker, solo hay que darle permisos.

```bash
docker exec -it nombre_contenedor chown -R www-data:www-data /var/www/html/wp-content
```
