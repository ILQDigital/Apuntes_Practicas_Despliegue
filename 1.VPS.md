# Configuración Inicial de un Servidor VPS

Esta guía explica paso a paso qué es un servidor **VPS**, cómo acceder a él por primera vez mediante **SSH**, cómo configurar un usuario con permisos de administración, cómo asegurar la máquina mediante un **firewall** (`ufw`) y cómo habilitar el acceso mediante **claves SSH** sin contraseña.

---

## ¿Qué es un VPS?

**VPS** significa *Virtual Private Server* (servidor privado virtual). Es un **ordenador remoto** ubicado en el centro de datos de un proveedor de alojamiento. Se controla a distancia ejecutando comandos desde la terminal de tu ordenador.

- **Es virtual:** El proveedor divide un servidor físico potente en varios servidores independientes. Cada uno tiene su propio sistema operativo (habitualmente Linux), su propia memoria RAM, almacenamiento y dirección IP.
- **Es privado:** Aunque comparta la máquina física con otros clientes, tu VPS está completamente aislado. Nadie más puede acceder a tus archivos ni datos.

### ¿Para qué sirve un VPS?
Sirve para mantener servicios funcionando **las 24 horas del día, los 365 días del año** sin depender de tu portátil local: páginas web, APIs, bases de datos, aplicaciones en contenedores Docker, automatizaciones como n8n, etc.

### Conceptos clave antes de empezar:
- **IP pública:** Dirección numérica única (ejemplo: `00.00.00.00`) que identifica al VPS en internet.
- **Sin interfaz gráfica:** La administración del VPS se realiza íntegramente por línea de comandos utilizando el protocolo **SSH**.

---

## ¿Qué es SSH?

**SSH** (*Secure Shell*) es el protocolo seguro utilizado para **abrir una consola remota** desde tu ordenador hacia el servidor con todo el tráfico cifrado de extremo a extremo.

> [!NOTE]
> En este manual, la dirección `00.00.00.00` representa la **IP pública real** de tu VPS, y `miusuario` representa el nombre de usuario administrado que desees crear.

---

## 1. Conexión inicial como `root`

Para la primera conexión, utiliza el usuario administrador `root` y la IP de tu VPS:

```bash
ssh root@00.00.00.00
```

Tras introducir la contraseña facilitada por el proveedor, puedes comprobar el sistema operativo y el kernel ejecutando:

```bash
uname -a
```

---

## 2. Creación de un usuario administrador

> [!IMPORTANT]
> **Por qué no se debe trabajar siempre como `root`:**  
> El usuario `root` posee permisos absolutos sin restricciones. Un comando erróneo o mal formateado puede dañar el sistema operativo. Crear un usuario normal que utilice `sudo` para tareas administrativas actúa como una red de seguridad esencial.

### Paso 2.1: Crear el nuevo usuario

```bash
adduser miusuario
```

El sistema solicitará una contraseña para el nuevo usuario (anótala) y algunos datos opcionales que puedes omitir pulsando la tecla `Enter`.

Para verificar que el usuario se ha creado correctamente en el sistema:

```bash
cat /etc/passwd
```

### Paso 2.2: Asignar permisos de administrador (`sudo`)

En Linux, los permisos se gestionan mediante grupos. El grupo `sudo` permite a sus miembros ejecutar comandos con privilegios elevados.

```bash
usermod -aG sudo miusuario
```

- `-aG`: La opción `-a` (*append*) añade el usuario al grupo (`G`) especificado sin eliminarlo de sus otros grupos.

## 3. Configuración de seguridad con el Firewall (`ufw`)

Un **firewall** (cortafuegos) es un filtro de red que determina qué conexiones entrantes se permiten y cuáles se rechazan. Por seguridad, el criterio por defecto es **bloquear todo excepto lo expresamente autorizado**.

### Paso 3.1: Permitir SSH antes de activar el firewall

```bash
ufw allow OpenSSH
```

> [!WARNING]
> **Paso crítico de seguridad:**  
> Debes permitir la regla de `OpenSSH` **antes** de habilitar el firewall. Si activas `ufw` sin este paso, perderás la conexión y quedarás bloqueado fuera del VPS.

### Paso 3.2: Activar y verificar el firewall

```bash
ufw enable
ufw status
```

### Paso 3.3: Abrir puertos para servicios Web (HTTP / HTTPS)

Un **puerto** es el punto final de comunicación. La IP identifica a la máquina y el puerto al servicio específico (el puerto `80` es HTTP no cifrado y el puerto `443` es HTTPS cifrado):

```bash
sudo ufw allow http
sudo ufw allow https
```

## 4. Habilitar el acceso SSH mediante claves (Sin Contraseña)

1. Cierra la sesión de `root`:

```bash
exit
```

2. Vuelve a acceder con el usuario recién creado:

```bash
ssh miusuario@00.00.00.00
```

### ¿Cómo funciona un par de claves SSH?

Un par de claves se compone de dos archivos matemáticamente vinculados:

- **Clave privada (`id_ed25519`):** Permanece **exclusivamente en tu ordenador local**. Es tu llave secreta.
- **Clave pública (`id_ed25519.pub`):** Se copia en el servidor remoto al que deseas acceder (la cerradura).

### Paso 4.1: Generar el par de claves en tu ordenador local

Ejecuta el siguiente comando en la terminal de tu PC:

```bash
ssh-keygen
```

Las claves se guardarán en el directorio oculto `~/.ssh/`. Puedes listar el contenido con:

```bash
cd ~/.ssh
ls -la
```

Verás los dos archivos: la clave privada (sin extensión) y la clave pública (`.pub`).

### Paso 4.2: Copiar la clave pública al VPS

Para acceder desde tu PC al VPS sin contraseña, copia el contenido de tu clave pública local (`id_ed25519.pub`) y pégalo dentro del archivo `~/.ssh/authorized_keys` del VPS.

> [!IMPORTANT]
> **Dirección del intercambio de claves:**  
> - **PC $\rightarrow$ VPS:** La clave pública de tu ordenador se guarda en `~/.ssh/authorized_keys` del VPS para poder conectarte por SSH sin clave.  
> - **VPS $\rightarrow$ GitHub:** Las claves generadas *dentro del VPS* sirven para autenticar el VPS contra servicios externos como GitHub (ver [5.App_web_Docker.md](5.App_web_Docker.md)).

Una vez agregada la clave pública al archivo `authorized_keys` de la máquina virtual, las futuras conexiones SSH desde tu PC se realizarán de forma directa y segura sin solicitar contraseña.
