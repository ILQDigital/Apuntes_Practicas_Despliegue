# Configuración Inicial de un Servidor VPS

Esta guía explica paso a paso qué es un servidor **VPS**, cómo acceder a él por primera vez mediante **SSH**, cómo configurar un usuario con permisos de administración, cómo asegurar la máquina mediante un **firewall** (`ufw`) y cómo habilitar el acceso mediante **claves SSH** deshabilitando por completo el acceso por contraseña.

---

## ¿Qué es un VPS?

**VPS** significa _Virtual Private Server_ (servidor privado virtual). Es un **ordenador remoto** ubicado en el centro de datos de un proveedor de alojamiento. Se controla a distancia ejecutando comandos desde la terminal de tu ordenador.

- **Es virtual:** El proveedor divide un servidor físico potente en varios servidores independientes. Cada uno tiene su propio sistema operativo (habitualmente Linux), su propia memoria RAM, almacenamiento y dirección IP.
- **Es privado:** Aunque comparta la máquina física con otros clientes, tu VPS está completamente aislado. Nadie más puede acceder a tus archivos ni datos.

### ¿Para qué sirve un VPS?

Sirve para mantener servicios funcionando **las 24 horas del día, los 365 días del año** sin depender de tu portátil local: páginas web, APIs, bases de datos, aplicaciones en contenedores Docker, automatizaciones como n8n, etc.

### Conceptos clave antes de empezar:

- **IP pública:** Dirección numérica única (ejemplo: `00.00.00.00`) que identifica al VPS en internet.
- **Sin interfaz gráfica:** La administración del VPS se realiza íntegramente por línea de comandos utilizando el protocolo **SSH**.

---

## ¿Qué es SSH?

**SSH** (_Secure Shell_) es el protocolo seguro utilizado para **abrir una consola remota** desde tu ordenador hacia el servidor con todo el tráfico cifrado de extremo a extremo.

> [!NOTE]
> En este manual, la dirección `00.00.00.00` representa la **IP pública real** de tu VPS, y `miusuario` representa el nombre de usuario administrado que desees crear.

---

## 1. Conexión inicial como `root`

Para la primera conexión, utiliza el usuario administrador `root` y la IP de tu VPS:

```bash
ssh root@00.00.00.00
```

Tras introducir la contraseña facilitada por el proveedor, puedes comprobar el sistema operativo y el kernel ejecutando:

```bash
uname -a
```

---

## 2. Creación de un usuario administrador

> [!IMPORTANT]
> **Por qué no se debe trabajar siempre como `root`:**  
> El usuario `root` posee permisos absolutos sin restricciones. Un comando erróneo o mal formateado puede dañar el sistema operativo. Crear un usuario normal que utilice `sudo` para tareas administrativas actúa como una red de seguridad esencial.

### Paso 2.1: Crear el nuevo usuario

```bash
adduser miusuario
```

El sistema solicitará una contraseña para el nuevo usuario (anótala) y algunos datos opcionales que puedes omitir pulsando la tecla `Enter`.

Para verificar que el usuario se ha creado correctamente en el sistema:

```bash
cat /etc/passwd
```

### Paso 2.2: Asignar permisos de administrador (`sudo`)

En Linux, los permisos se gestionan mediante grupos. El grupo `sudo` permite a sus miembros ejecutar comandos con privilegios elevados.

```bash
usermod -aG sudo miusuario
```

- `-aG`: La opción `-a` (_append_) añade el usuario al grupo (`G`) especificado sin eliminarlo de sus otros grupos.

## 3. Configuración de seguridad con el Firewall (`ufw`)

Un **firewall** (cortafuegos) es un filtro de red que determina qué conexiones entrantes se permiten y cuáles se rechazan. Por seguridad, el criterio por defecto es **bloquear todo excepto lo expresamente autorizado**.

### Paso 3.1: Permitir SSH antes de activar el firewall

```bash
ufw allow OpenSSH
```

> [!WARNING]
> **Paso crítico de seguridad:**  
> Debes permitir la regla de `OpenSSH` **antes** de habilitar el firewall. Si activas `ufw` sin este paso, perderás la conexión y quedarás bloqueado fuera del VPS.

### Paso 3.2: Activar y verificar el firewall

```bash
ufw enable
ufw status
```

### Paso 3.3: Puertos web (HTTP / HTTPS)

Un **puerto** es el punto de entrada de un servicio: la IP identifica a la máquina y el puerto al servicio (`80` = HTTP, `443` = HTTPS).

**Con Cloudflare Tunnel (como en estos apuntes) no hay que abrir el 80 ni el 443**: el túnel usa una conexión de salida. Déjalos cerrados. Solo si no usas túnel:

```bash
sudo ufw allow http
sudo ufw allow https
```

> [!WARNING]
> Docker se salta `ufw`: un puerto publicado con `-p 8080:8080` queda abierto a Internet aunque `ufw` lo bloquee. Por eso en estos apuntes se publica como `127.0.0.1:8080:8080` (solo accesible desde el propio VPS).

## 4. Habilitar el acceso SSH mediante claves (sin contraseña)

Si tu servidor tiene el puerto SSH expuesto a internet, es un objetivo constante de bots que prueban usuarios y contraseñas al azar (sobre todo `root`). La defensa más eficaz no es "esconder" el servidor, sino **eliminar la posibilidad de entrar con contraseña** y exigir clave SSH.

### ¿Cómo funciona un par de claves SSH?

Un par de claves se compone de dos archivos matemáticamente vinculados:

- **Clave privada 🔒 (`id_ed25519`):** Permanece **exclusivamente en tu ordenador local**. Nunca se comparte. Es la que demuestra que eres tú.
- **Clave pública 🔑 (`id_ed25519.pub`):** Se copia en el servidor remoto, en `~/.ssh/authorized_keys`. No es secreta.

Al conectar, tu PC usa la clave privada para demostrar que tiene la pareja de la clave pública guardada en el servidor. Si coinciden, entras. El proceso es matemáticamente irreversible: de la pública nunca se puede reconstruir la privada.

### Paso 4.1: Acceder con el nuevo usuario

1. Cierra la sesión de `root`:

```bash
exit
```

2. Vuelve a acceder con el usuario recién creado:

```bash
ssh miusuario@00.00.00.00
```

### Paso 4.2: Generar el par de claves en tu ordenador local

Ejecuta el siguiente comando en la terminal de tu PC:

```bash
ssh-keygen -t ed25519
```

Las claves se guardarán en el directorio oculto `~/.ssh/`. Puedes listar el contenido con:

```bash
cd ~/.ssh
ls -la
```

Verás los dos archivos: la clave privada (sin extensión) y la clave pública (`.pub`).

### Paso 4.3: Copiar la clave pública al VPS

Desde tu PC, el método más fácil:

```bash
ssh-copy-id miusuario@00.00.00.00
```

(Hace lo mismo que copiar a mano el contenido de `id_ed25519.pub` al archivo `~/.ssh/authorized_keys` del VPS.) Prueba con `ssh miusuario@00.00.00.00`: ya no debe pedir la contraseña del servidor.

> [!IMPORTANT]
> **Dirección del intercambio de claves:**
>
> - **PC → VPS:** la clave pública de tu ordenador se guarda en `~/.ssh/authorized_keys` del VPS.
> - **VPS → GitHub:** otra clave, generada _dentro del VPS_ (ver [2.Git.md](2.Git.md)).

### Paso 4.4: Deshabilitar el acceso por contraseña en el servidor

Con el acceso por clave ya funcionando, el siguiente paso es **eliminar completamente la posibilidad de entrar con contraseña** editando la configuración del servicio SSH:

```bash
sudo nano /etc/ssh/sshd_config
```

Busca y establece las siguientes directivas:

```
PermitRootLogin no
PasswordAuthentication no
```

- **`PermitRootLogin no`** → `root` no puede entrar por SSH bajo ninguna forma (ni con clave ni con contraseña). Alternativa intermedia: `prohibit-password` (root solo puede entrar con clave SSH, nunca con contraseña).
- **`PasswordAuthentication no`** → obliga a usar clave SSH para cualquier usuario. Elimina casi por completo los ataques de fuerza bruta.

Tras editar el fichero, reinicia el servicio SSH para aplicar los cambios:

```bash
sudo systemctl restart ssh
```

> [!IMPORTANT]
> ⚠️ **Aviso importante antes de aplicar `PasswordAuthentication no`:**
>
> 1. Comprueba que el acceso por clave SSH **ya funciona** antes de desactivar las contraseñas.
> 2. Al probar el cambio, abre una **segunda terminal nueva** y confirma que puedes entrar bien con la clave **sin cerrar la sesión actual**. Así, si algo falla, la sesión abierta permite corregirlo.

---

## 5. Guardar a salvo la clave privada

Si formateas el PC sin haber guardado copia de la **clave privada**, esta se pierde para siempre (no se puede recuperar desde la pública). Con `PasswordAuthentication no` activo, eso significa quedarse fuera del servidor sin ninguna forma de entrar por SSH.

Recomendaciones:

- Hacer copia de seguridad de la **clave privada** en un sitio seguro (USB cifrado, gestor de contraseñas...).
- Tener un plan B de acceso:
  - Servidor físico en casa → acceso directo con teclado/monitor.
  - VPS → consola web de emergencia del proveedor.
  - Una segunda clave SSH de respaldo, generada en otro dispositivo y guardada aparte.
