# Fundamentos e Instalación de Docker en el VPS

Esta guía explica qué es **Docker**, la diferencia clave entre sus conceptos principales (**Dockerfile**, **Imagen** y **Contenedor**), el uso de **puertos** y **volúmenes**, y los pasos para instalarlo y administrarlo en un servidor VPS.

---

## ¿Qué es Docker?

**Docker** es una plataforma que permite **empaquetar una aplicación junto con todas sus dependencias** (versión de Python, librerías, configuraciones, etc.) en un entorno aislado denominado **contenedor**.

### ¿Por qué se utiliza Docker?
Resuelve el problema clásico: *"En mi ordenador funcionaba, pero en el servidor no"*. Con Docker, la aplicación no depende del software instalado previamente en la máquina anfitriona, garantizando un comportamiento idéntico en cualquier servidor.

---

## Los tres conceptos fundamentales

| Concepto | Definición | Analogía gráfica |
| :--- | :--- | :--- |
| **Dockerfile** | Archivo de texto plano con las instrucciones para construir la aplicación. | La receta / El plano |
| **Imagen** | Paquete cerrado de solo lectura generado al ejecutar el Dockerfile. | El instalador / Programa |
| **Contenedor** | Instancia en ejecución basada en una imagen. | El programa abierto en memoria |

> [!NOTE]
> A partir de **una sola imagen** puedes crear y ejecutar **múltiples contenedores** independientes. Eliminar un contenedor no borra la imagen base.

---

## Redes (Puertos) y Persistencia (Volúmenes)

### 1. Mapeo de Puertos (`-p`)
Los contenedores están aislados por defecto. Si una aplicación escucha en el puerto `8080` *dentro* del contenedor, no será accesible desde fuera hasta que vincules un puerto del VPS con el puerto interno del contenedor (formato: `-p puerto_vps:puerto_contenedor`).

### 2. Volúmenes Persistentes (`-v`)
Por defecto, los datos generados dentro de un contenedor son efímeros y **se borran si el contenedor se elimina**. Un **volumen** conecta un directorio del VPS con un directorio interno del contenedor (formato: `-v ~/nombre_carpeta:/app`), asegurando que las bases de datos (SQLite, PostgreSQL, etc.) y los archivos subidos sobrevivan a los reinicios.

---

## Diferencia entre Contenedores y Máquinas Virtuales (VM)

- **Máquina Virtual:** Incluye un sistema operativo completo con su propio kernel, lo que requiere gigabytes de espacio y mayor tiempo de arranque.
- **Contenedor:** Comparte el kernel del sistema operativo del servidor anfitrión (*Linux*) y solo incluye las dependencias necesarias. Se ejecuta en segundos y consume muy pocos recursos.

## Instalación de Docker en el VPS

> [!NOTE]
> Todos los comandos de esta sección deben ejecutarse **dentro del VPS** vía SSH (ver [1.VPS.md](1.VPS.md)).

### Paso 1: Descargar e instalar el script oficial de Docker

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```

- `curl -fsSL`: Descarga el archivo de instalación desde el sitio oficial de Docker.
- `sudo sh get-docker.sh`: Ejecuta el script con permisos de administrador.

### Paso 2: Verificar la instalación

```bash
docker --version
```

### Paso 3: Configurar permisos de usuario sin `sudo`

Por defecto, Docker requiere permisos de superusuario (`root`). Para poder ejecutar comandos de Docker con tu usuario habitual, añádelo al grupo `docker`:

```bash
sudo usermod -aG docker $USER
```

- `$USER`: Variable de entorno del sistema que contiene el nombre de tu usuario activo.

> [!IMPORTANT]
> **Requisito de reinicio de sesión:**  
> Para que el cambio de grupo surta efecto, debes **cerrar la sesión SSH y volver a conectarte** (o ejecutar `newgrp docker`).

### Paso 4: Comprobar la membresía del grupo

```bash
groups
```

### Paso 5: Prueba de funcionamiento sin `sudo`

```bash
docker run hello-world
```

*(Docker descargará una imagen de prueba, la ejecutará en un contenedor y mostrará un mensaje confirmando que la instalación es correcta).*

## Comandos más usados en Docker

```bash
# Listar contenedores en ejecución
docker ps

# Listar todos los contenedores (incluyendo los detenidos)
docker ps -a

# Listar las imágenes descargadas o construidas en el VPS
docker images

# Ver las salidas y logs de un contenedor (imprescindible para depurar errores)
docker logs nombre_contenedor

# Detener un contenedor en marcha
docker stop nombre_contenedor

# Iniciar un contenedor detenido
docker start nombre_contenedor

# Eliminar un contenedor (la flag -f fuerza el borrado si está activo)
docker rm -f nombre_contenedor

# Eliminar una imagen del sistema
docker rmi -f nombre_imagen

# Abrir una terminal interactiva dentro del contenedor activo
docker exec -it nombre_contenedor bash
```
